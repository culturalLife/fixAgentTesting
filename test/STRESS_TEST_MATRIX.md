## How to read a failed row

- **Traps 1, 2, 4, 6** with no anomaly detected → judge rubric gap. Fix the judge's scoring instructions, not the engine.
- **Trap 3** producing `TOOL_UNNECESSARY_CALL` → confirms the engine bug, independent of judge quality. Fix is in `trace_eval_service.py`, not the judge.
- **Trap 5** → decide the intended precedence rule first (should a crashed span always be `SPAN_EXCEPTION_ERROR` regardless of what the Goal judge separately concludes?), then check whether the code matches it.
- **Trap 7, 8** with no anomaly at all → this is the most important failure mode to find, since it means the judge suite has a blind spot for "technically successful, substantively wrong" traces — the exact case judges exist for for that deterministic checks can't catch.
- **Trap 9** → run it in isolation with `verbose=True` and log `all_judges[0]["id"]` right before the call in `generate_remediation_card()`, then compare against which judge actually fired for this trace.
